# 接口边界与工作流

> 这页解释「为什么做不到某些事」，以及把 HTML 写进有道笔记时的具体约定。
> 只描述公开接口（有道官方 CLI + MCP），不涉及任何非公开通道。

---

## 1. 官方接口能给什么

| 能力 | 行为 |
|---|---|
| 目录列表 | 分页返回 `fileId` / 标题 / 类型 |
| 读笔记 | 返回**纯文本**（`.md` / `.txt` 会原样返回） |
| 搜索 | 标题 + 正文，每页固定 15 条 |
| 新建笔记 | 支持 HTML 内容；可指定目录 `parentId` |
| 带图新建 | 图片以 base64 提交，走官方上传链路 |
| 网页剪藏 | 给 URL，存到指定目录 |
| 修改 `.md` | 整体覆盖，仅限 `.md` 笔记 |
| 修改富文本 | **不提供** |
| 删除 / 移动 / 重命名 | 只有部分客户端能力，接口层不保证 |

CLI 的 `list` / `read` / `search` / `save` / `clip` 子命令分别对应上表。

---

## 2. 为什么不能「原地改」一篇富文本笔记

1. **读出来只有文字**。返回体里带一个 `isRaw` 字段：`.md` / `.txt` 为 `true`，其余笔记是「经处理转为纯文本」。
   实测一篇约 400 字的富文本笔记，读回来是一段连续文字：换行没了、表格塌成一行、图片位置全丢；
   内容以截图为主的那类笔记，读出来只剩一两百字。
2. **写只能新建**。`save` 接受的类型只有 `note` / `md` / `mindmap2`。
   想以富文本类型写入，`content` 必须是编辑器内部的专有 JSON 结构（无公开 schema），CLI 层直接校验拒绝。
3. **没有 update 富文本的方法**。唯一的更新方法是 `updateMarkdownNote`，非 `.md` 直接报错。

结论：**读只能拿纯文本、写只能新建**。硬做「读 → 改 → 写」等于把手写富文本降级成一段纯文字，比不改更糟。

（另有网页端内部接口可以做到，但属于非公开接口：需要浏览器 Cookie、结构无文档、随版本变化失效，不建议作为主线。）

## 3. 三条落地路径

| 场景 | 命令 | 之后做什么 |
|---|---|---|
| 往已有笔记里补内容 | `python tools\ynote.py clip --html-file 片段.html` | 编辑器里定位光标，`Ctrl+V` |
| 片段里要带截图（真实上传） | `python tools\ynote.py save-html --title "临时子笔记" --html-file 片段.html --image 截图.png` | 打开子笔记 → 全选复制 → 粘到目标笔记 → 删掉子笔记 |
| 备份 / 本地检索整库 | `python tools\ynote_snapshot.py --out <目录>` | 只有文字，当检索和 diff 用；真正的兜底是客户端的「笔记历史」 |

**为什么带图要走第二种**：剪贴板里的 `<img src="data:...">` 粘贴后不会上传到图床，图片会丢或变成外链；
`save-html` 的 base64 图片走官方上传链路，一定能显示。

## 4. 格式保真度

| HTML | 有道富文本 | 备注 |
|---|---|---|
| `<table>` | ✅ 真表格、有框线 | 表头用 `<thead><th>` |
| `<ul>` / `<ol>` | ✅ 圆点 / 1. 2. | |
| `<b>` `<i>` `<u>` | ✅ | 也认 `<strong>` `<em>` |
| `<del>` / `<s>` | ✅ 删除线 | |
| `span style="color:#C00000"` | ✅ | **必须用 span style** |
| `<font color>` | ❌ 掉色 | 别用 |
| 行内 `<code>` | ✅ 灰底 | |
| 围栏 `<pre><code>` | ✅ 真代码块，带行号 | 贴命令最合适 |
| `<blockquote>` | ✅ 左侧竖线缩进 | 没有底色，靠竖线区分 |
| 图片 | ✅（只走 `save-html --image`） | 见 §3 |
| 中文 | ✅（剪贴板必须用 `ynote_clip.py`） | PowerShell 自带命令会全变 `◆` |

## 5. 生成 HTML 片段的约定

- 文件一律 UTF-8 无 BOM；可以直接用浏览器打开预览。
- 颜色只写 `<span style="color:#RRGGBB">`；字号尽量别写死，有道会按「正文 / 标题」重排。
- 命令一律用 `<pre><code>`，一行一条——让编辑器自己换行会很难读。
- 表格别超过 4 列，正文宽度有限。
- 不要把 HTML 直接塞进命令行参数（引号会被 shell 吃掉），**写文件后走 `--html-file`**。

## 6. 快照的结构与局限

```
<out>\
├─ 某目录\子目录\笔记标题.md     ← 头部注释：fileId / 原目录 / 抓取时间
├─ index.csv                    ← fileId, 标题, 相对路径, 字符数, 时间
└─ _SUMMARY.txt                 ← 篇数 / 总字数 / 失败清单
```

- **只有文字**：图片、脑图、白板、附件、表格结构全部丢失，字数会明显少于肉眼所见。
- 适合：全文检索、版本 diff、把自己写的文字交给 AI 读。
- 不适合：当作富文本备份。

## 7. 坑清单

1. `Session not found: <uuid>` —— MCP 走 SSE，会话会过期。`read` 已内置 2 次重试；偶发超时重跑即可。
2. `fileId` 大小写敏感，抄错一位就是「笔记不存在」。
3. `delete` 没有二次确认，脚本里必须带 `--yes`；删掉的笔记进客户端回收站（保留期以有道为准）。
4. 判断目录不能靠后缀：`save-html` 建的富文本笔记标题没有 `.note` 后缀，要按 `list` 输出行首的 📁 / 📄 判断。
5. 命令行参数过长会出问题：内容优先走 `--html-file`，别用 `--html "..."`。
6. 换 Key 会写用户目录配置，某些受限环境下需要更高权限。
